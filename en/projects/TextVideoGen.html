An OpenCode-driven local video production workspace. You supply only the script, the communicative goal and the business constraints; agents take on creative proposals, direction, storyboards, assets, production, checks and revision so the audience understands the content on first viewing — with code, video projects and the runtime kept apart.

At a glance

TextVideoGen splits local video production into 13 reviewable stages: script, voice, alignment, creative treatment, direction, storyboard, assets, per-scene rendering, composition, QA, final review, revision and delivery. Structured contracts record the inputs and outputs of each stage, so a change only reruns the scenes it affects; every scene can be produced as HTML/SVG motion, an image, a hybrid or B-roll.

  • Reproducible locallyRuntime, source and finished film are managed separately.
  • Scene-level revisionImpact analysis and hash verification allow unchanged scenes to be reused.
  • Gated deliveryAutomated QA and human review decide which version is deliverable.

About this project

What it addresses

Generated video commonly suffers from processes that cannot be reviewed and from whole-run reruns after a local change. TextVideoGen leaves you responsible only for the script, the goal and the constraints; agents handle the rest, and production is split into stages governed by contracts, so the inputs, outputs, versions and review decisions of every step remain traceable.

How the pipeline is organised

A project contract comes first, then agents propose two or three producible creative treatments and recommend one. Narration, timing alignment, direction, storyboard and scene assets follow in order; after per-scene rendering, technical QA runs and a delivered version is produced only once human review passes. When something changes, impact analysis comes first.

What it uses

OpenCode schedules the multi-stage tasks; Voicebox handles narration, WhisperX handles timing alignment, rendering runs on HTML / SVG Motion with Playwright, and composition uses FFmpeg. JSON Schema and hashes record the input-output relationships.

Current status

The v0.1.0 source release is published and the workspace currently supports macOS Apple Silicon. Historical generation artefacts were cleared during the packaging pass; old projects keep only their source scripts and cleanup logs, and production restarts from the script stage.

Getting started and everyday commands

Every entry point lives in bin/, with separate commands for setup, projects, logging, delivery and packaging.

Prepare the environment

./bin/setup installs the runtime, dependencies, browser and models into .videoenv; ./bin/check-environment only inspects, running no model inference.

Create and produce

./bin/new-project my-video "Title" scaffolds a project, then ./bin/opencode-video hands production to the agents.

Log and check

./bin/video-log records stage events, and ./bin/pnpm-video check combines type, isolated-environment and Voicebox checks.

Safe delivery and recoverability

The workspace concentrates on production; the finished film only moves into the macOS Movies folder once it has been approved.

No overwrite

./bin/deliver-video never overwrites an existing version and records the destination path, file size and SHA-256.

Code and film kept apart

The final video leaves the repository, leaving only a committable delivery record and full production provenance.

Rebuildable environment

Deleting .videoenv leaves source and projects untouched; rerunning ./bin/setup restores the pinned environment.

Source release packages

./bin/package-workspace builds a source package without private projects or the runtime; the v0.1.0 package is about 22 MB.

Publishable content only

Code, configuration, lockfiles, shared assets and the Skills / plugin sources travel; Git metadata, dependencies, models, caches, logs, credentials and old projects do not.

Separate output folder

Each run writes to .videoenv/tmp/packages/release-<time>-<random>/, so earlier archives and checksums are never overwritten.

Verify, then install

A SHA-256 checksum ships alongside the archive; unpack it into a new directory and run ./bin/setup to rebuild the pinned environment.
