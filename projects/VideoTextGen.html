文本视频生成流

由 OpenCode 调度的本地视频生产工作区。它把创意提案、脚本、配音、字幕对齐、导演方案、分镜、素材、逐场景渲染、合成、QA、返修和交付统一进结构化流程，同时把运行环境、可提交源码与最终成片彼此隔离。

项目速览

VideoTextGen 将本地视频制作拆分为 12 个可审查阶段：脚本、配音、字幕对齐、导演方案、分镜、素材、逐场景渲染、合成、质检、返修与交付。结构化契约记录每个阶段的输入与输出，变更时仅重做受影响的场景。页面展示的 18 场景样例已通过技术 QA，并保留成片帧与核验数据。

  • 本地可复现运行环境、源码和最终成片分离管理。
  • 按场景返修影响分析与哈希校验支持复用未变化的场景。
  • 交付有门禁自动 QA 与人工审查决定可交付版本。

关于这个项目

它要解决什么

生成式视频的常见问题是过程难以复查、局部修改需要整体重跑。本项目将制作流程拆分为带契约的阶段，使每一步的输入输出、版本与审查结论都可追溯。

流程如何组织

先建立项目契约与创意方案，再依次生成配音、时间对齐、分镜与场景素材；逐场景渲染后运行技术 QA，人工审查通过方可生成交付版本。发生变更时先进行影响分析。

用到什么

由 OpenCode 调度多阶段任务；配音使用 Voicebox，时间对齐使用 WhisperX，画面渲染基于 HTML Motion 与 Playwright，合成由 FFmpeg 完成；JSON Schema 与哈希值记录输入输出关系。

把“生成视频”变成工程

每个阶段都有明确输入、结构化产物、版本与审查门禁，便于复现每次生成和审查过程。

运行环境隔离

Node、Python、Playwright、FFmpeg、WhisperX 与模型全部进入 .videoenv，不污染全局环境。

结构化契约

项目、脚本、创意方案、分镜、时间线、返修与场景素材均由 JSON Schema 约束。

全链路溯源

每次 provider 调用、阶段完成、审查结论和交付记录都会保留版本与输入关系。

最小化返修

先生成影响分析，只重做受变更影响的场景；未变化场景通过哈希验证直接复用。

生产流水线

GPT 负责创意、导演与门禁；经济模型处理可复核的格式化和初检任务。

01—02Script + Voice

脚本结构化，Voicebox 本地配音。

03—04Align + Direct

WhisperX 对齐，生成创意与导演方案。

05—06Storyboard + Assets

拆分场景，绑定文本和素材来源。

07—08Render + Compose

逐场景渲染，时间线精确合成。

09—10QA + Review

技术检测后进入人工审查门禁。

11—12Revise + Deliver

局部返修，获批版本原子化交付。

从 HTML Motion 到最终视频

浏览器逐帧渲染与 FFmpeg 媒体管线协作，既保留前端动画的表达力，也控制视频时序。

01 · Scene

场景描述

分镜绑定字幕、素材清单与视觉签名。

02 · Browser

Playwright

HTML / SVG 场景按帧生成 JPEG 图像流。

03 · Encode

FFmpeg

image2pipe 直接编码，避免海量临时帧。

04 · Compose

精确合成

单 filter graph 重定时、拼接并混入配音。

05 · Verify

自动 QA

校验解码、黑帧、静帧、静音、帧率和音画时长。

真实项目输出

“英语启蒙四关通关总纲”示例：1080 × 1920、30 fps、18 个场景，QA 检查通过。

QA 结果：18 个场景顺序完整；视频与音频时长差 0.011667 秒；无解码错误、黑帧或超过 0.8 秒的静音；返修只重渲染 9 个受影响场景，其余 9 个场景通过哈希验证复用。

安全交付与可恢复性

工作区专注于生产过程，最终成片只在获得批准后移入 macOS Movies 目录。

拒绝覆盖

交付命令不会覆盖同名版本，避免批准后的成片被无意替换。

代码与成片分离

最终视频移出仓库，只留下可提交的交付记录和完整生产溯源。

环境可重建

删除 .videoenv 不影响源码和 projects；重新运行 setup 即可恢复固定版本环境。

技术栈

本地模型、浏览器渲染与媒体处理在统一工作区中协作。
