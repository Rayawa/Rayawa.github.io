项目背景与四层架构

从一块仅提供原厂 Linux SDK 的昇腾 310B 套件出发，将开源鸿蒙系统与应用推理完整衔接在一起。

实验室配有一块搭载华为昇腾 310B NPU 的启智01 开发者套件。为了在板卡上运行 OpenHarmony 操作系统并切实调用板载 NPU 算力，项目拆分为上下两条工作线：底层完成 OpenHarmony 5.0.3 面向昇腾 310B 的系统移植，上层以 ArkTS 构建 Ascend X-Ray Expert 应用——读入胸部 X 光影像后运行 YOLOv5s 模型识别肺炎、结核等病变区域，并分别验证了 CPU（MindSpore Lite）与 NPU（CANN ACL）双推理通路。

OpenHarmony 系统移植

昇腾 310B 的硬件架构与 OpenHarmony 官方默认支持开发板差异较大，需从内核驱动、HAL 接口及构建工具链逐一适配打通。

GPU 图形渲染

引入面向 Mali GPU 的开源 Panfrost 驱动并搭配 GBM Gralloc，按照 OpenHarmony Display Composer VDI 规范实现 HAL 适配层，使桌面图形系统稳定运行。

HDMI 输出与双屏显示

打通 DRM/KMS 显示链路下的 HDMI 输出与双屏异显能力，梳理并解决 framebuffer 分配管理及 VSync 帧同步底层细节。

Camera 与音频子系统

完成 USB 与 MIPI CSI 摄像头的 V4L2 驱动接入，并适配 ALSA 声卡与 HDMI 音频播放通路。

NPU 推理与端侧大模型

部署板端 CANN 运行时与推理环境，在成功验证 YOLOv5 模型的同时，进一步在昇腾 310B 上跑通 MindIE Qwen3-0.6B 小尺寸语言模型。

01 主干补丁集成 向 OpenHarmony 主干整理合并 43 个专项 patch，覆盖 GN + Ninja 构建体系、HDF 驱动框架、GPU 2D/3D、SELinux 策略、V4L2 相机、ALSA 音频、多屏显示、HDC 调试及电源管理。
02 内核驱动移植 针对 Linux 5.10 交叉编译并移植 20 余个内核模块，涵盖 panfrost.ko（GPU）、svm.ko（NPU）、蓝牙/Wi-Fi 无线模组以及多款摄像头驱动。
03 基础工具链补齐 针对系统内置 toybox 缺少 awk、tr 等指令导致 Ascend HDK 安装脚本报错的问题，独立交叉移植了完整版 bash-5.1 与 busybox-1.36.1。
04 自动化编译与制卡 提供一键编译脚本 build.sh（自动拉取源码 → 合入 43 个 patch → 全量编译），以及制卡脚本 formatSD310B.sh（支持 Linux 直写 SD 卡或导出 BalenaEtcher 可用镜像）。

Ascend X-Ray Expert 应用

运行于 HarmonyOS 5.0.3 (API15) Stage 模型的胸部 X 光检查界面：医学影像具有高度隐私敏感性与即时反馈诉求，非常适合在边缘端 NPU 上就地完成推理。

五分类目标检测

利用 YOLOv5s 对输入的胸部 X 光图片执行目标检测与置信度过滤，区分以下五类状况：

细菌性肺炎 病毒性肺炎 患病（其他） 健康 结核病

MindSpore Lite (CPU 路径)

调用 HarmonyOS 系统内置的 MindSpore Lite Kit 加载 .ms 模型权重，启用 2 线程 CPU 推理。图像预处理（RGBA 转 float 归一化）与后处理逻辑（NMS 非极大值抑制、IoU 重叠度计算）全部在 ArkTS 侧独立编写实现。

CANN ACL (NPU 路径)

C++ 底层通过 dlopen 动态加载 libacl_runtime.so，依次调用 aclInit → aclrtSetDevice → aclrtCreateContext → aclrtCreateStream 初始化硬件上下文，并以 aclmdlLoadFromFile 载入 .om 离线模型；最终借助 NAPI 向 ArkTS 页面暴露 initYoloEngine 与 runYoloInference 接口。

Step 01 选择影像 通过系统 PhotoViewPicker 选取本地 X 光胸片，等比缩放至 640×640 并补齐 letterbox 黑边。
Step 02 张量预处理 将像素阵列由 RGBA 转换并归一化为 float32 输入张量，整理送入推理引擎。
Step 03 双擎推理 按需路由至 CANN ACL（NPU）或 MindSpore Lite（CPU）完成前向计算。
Step 04 后处理筛选 计算检测框 IoU 并执行 NMS 非极大值抑制，剔除置信度过低及重叠冗余框。
Step 05 三栏可视化结果 在 Canvas 上精确还原检测框，界面分为左栏原图对照、中栏统计图表与右栏历史记录。

全栈工程要点总结

贯穿系统底软、NAPI 原生桥接、端侧 AI 加速与大模型试跑的工程沉淀。

系统层与应用层垂直打通

完整走通从 Linux 内核模块编译、OpenHarmony HAL 接口实现到 ArkUI 应用上线的全链条工作。

双引擎协同对比验证

同时落地的 MindSpore Lite（CPU）与 CANN ACL（NPU）通路均可正常输出，实际观测 NPU 推理时延显著优于 CPU。

隐私敏感场景适配

胸部 X 光片辅助分析对数据安全与低延迟要求高，完全在板端 NPU 上离线推理无需依赖云端上传。

嵌入式大模型探索

基于 MindIE 在昇腾 310B 板卡上验证运行了 Qwen3-0.6B 模型，确认轻量级语言模型在边缘 NPU 部署的可行性。

自动化脚本复现

用 build.sh 整合源码获取、patch 合入与镜像编译步骤，大幅降低整套系统的构建复现成本。

NAPI 原生桥接

借助 CMake 构建的 C++ NAPI 扩展层，令 ArkTS 前端能直接持有 NPU 模型实例并调用硬件加速。
