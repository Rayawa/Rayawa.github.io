# 2026-10-30 粒子交互修复

修正 45f983e 中将 particles.js 的交互直接绑定到 window 的改动。此前库内置的鼠标抓取、点击新增与网站原有磁吸同时响应，普通链接点击也会新增粒子。现在只由原有磁吸处理指针，保留粒子间连线和本地粒子库。

同时处理原实现中的问题：

- 稀疏区域补充粒子有上限，与画布面积和原始密度相适应；只让补充粒子按生命周期淡出。
- 磁吸中心保留缓冲区，避免长时间停留将粒子压到同一点；自然漂移不再被持续阻尼到停止。
- 磁吸按实际处理间隔计算时间，首页画布视差移动时重新映射指针坐标。
- pagehide、pageshow、页面可见性与取消触摸时重置指针；恢复时只启动一个磁吸循环。首页视差同时重置，避免返回后沿用旧指针偏移。
- common.js 与 index.js 的所有页面引用统一带版本号，避免旧脚本缓存与新页面混用。

验证：`node --test tests/particles.test.cjs` 包含手机/桌面模拟长停留、全局点击隔离、减弱动态、返回恢复和数组刷新七项回归。首轮六项测试中旧实现有五项失败，包括 30 秒后手机尺寸 67 个粒子、桌面 114 个粒子超过预期范围；修复并补充数组刷新回归后，七项全部通过。此处为带正常漂移的确定性模拟，并非设备帧率测量。

浏览器使用临时本地诊断页连续点击 20 次普通链接，粒子从 90 到 91 个（包含正常的稀疏补充，仍在该画布 94 个上限内），没有内置抓取或点击新增。实际跳转项目与返回后保持一个画布，没有残留过渡遮罩。临时诊断页不纳入提交。

82 个页面、1191 个本地引用与共享脚本版本对应检查通过，两个脚本语法检查和 git diff --check 通过。
