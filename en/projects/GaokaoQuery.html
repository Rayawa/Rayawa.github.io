Batch Gaokao Result Query Tool

Turns the repetitive manual work of checking admission results one by one into a batch pipeline: the script reads a name list, queries, verifies and organises the results automatically, and finally exports a complete results spreadsheet.

Project Overview

The tool targets batch lookup scenarios. It uses Playwright to drive a browser against the admission-result query endpoint of the Beijing Education Examinations Authority, retrieves results one by one, structures the data with pandas, and writes an Excel file through openpyxl. Along the way it checks whether names match, and records cases such as missing results or empty majors separately, producing a summary table that a person can review.

  • Batch lookupsThe name list is read from a spreadsheet and every query completes in one pass, removing the repeated manual work.
  • Results you can auditName mismatches, empty query results and blank majors are each flagged separately so a person can review them.
  • Dependencies prepared automaticallyThe first run checks for pandas, playwright and openpyxl and installs anything missing.

About This Project

What it sets out to do

Admission-result lookups require entering information and recording outcomes one entry at a time, which becomes error-prone and easy to miss as the list grows. This tool merges querying, verification and organisation into a single step.

How it runs

The script first confirms that dependencies are present and installs anything missing; it then reads the list to query and uses Playwright to drive a browser against the query endpoint, recording each result as it arrives; finally it writes everything out to Excel. Every result is checked against the name in the list, and mismatches are marked separately.

What it uses

Written in Python; Playwright for browser automation; pandas for data handling; openpyxl for spreadsheet export.

Scope and limits

The tool targets batch organisation, and results follow whatever the official endpoint returns; network failures or endpoint changes require manual confirmation. Personal information is processed only on the local machine and is never transmitted elsewhere.

Workflow

From reading the list to exporting the spreadsheet, four steps run in order.

Check and prepare dependencies

The first run detects whether pandas, playwright and openpyxl are available and installs what is missing, so environment problems do not interrupt the flow.

Read the list to query

Entries to look up are loaded from a spreadsheet as the input for the whole batch.

Query and verify one by one

A browser is driven against the query endpoint to fetch results, and each one is compared with the name in the list, with mismatches flagged separately.

Organise and export

pandas structures the results and openpyxl writes an Excel summary table that can be inspected and reviewed directly.

Anomalies recorded separately

Missing results and empty admission majors are not silently dropped but sorted into their own categories.

Data stays local

All processing happens on the local machine; neither the name list nor the results are uploaded to any third-party service.
