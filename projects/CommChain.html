基于 C# 的数字通信系统模拟器

把课本里的抽象通信原理，变成屏幕上一步步看得见的信号旅程。输入一句文字，就能亲眼看着它被霍夫曼压缩、打上校验帧、穿过最短路由与模拟噪声信道，最终在另一端准确无误地还原回来。

C# / .NET 10 零第三方依赖 Huffman · CRC-8 Hamming (7,4) Dijkstra / Floyd ASK / FSK xUnit (50+ 用例)
dotnet run --project src/CommChain.App

把通信原理变成看得见的信号旅程

不依赖任何第三方算法包，左侧看它能带你做什么实验，右侧直接切换三档信道误码仿真输出对照。

从文本到比特的压缩之旅

输入一段话即可自动统计字频、画出前缀码表并算出相对 8-bit 定长编码节省的比特率，让熵编码不再停留在公式纸面上。

亲手制造错码，看纠错与校验接力

既能用 CRC-8 揪出被篡改的数据包，也能给 7 位汉明码手动翻转任意一比特，亲眼看着接收端算出校验子把错误原地掰正。

看得见的路由路径与 ASCII 波形

从拓扑配置文件自动规划出最短传输路径，并直接把 0/1 比特流调制后的 ASK 振幅与 FSK 频率波动在控制台画出来。

三档噪声压测，结果可复现

一键启动全链路仿真，从零干扰、单错自愈到高频双错触发 CRC 丢帧保护全过程清晰呈现；50 多项固定种子单测保证每次验证稳妥一致。

九阶段端到端通信链路

在完整链路模式下，原始文本会沿着类似 OSI 分层的结构依次穿越下面五个关键处理层。

表示层 · Stage 2 霍夫曼信源编码 统计字符频次后建树生成前缀码，压缩比特流并将码表与有效位长打进 META 帧一并发送。
链路层 · Stage 3 组帧与 CRC-8 (0x07) 封装帧头 [type / source / dest / seq / len] 与载荷，尾部附加 CRC-8 校验字节形成 META 与 DATA 帧。
网络层 · Stage 4 队列分流与 Dijkstra 路由 将业务帧和随机背景噪声包混合入队，再按目的 ID 分流并依据拓扑文件计算最短路径。
物理层 · Stage 5–6 汉明码 (7,4) + ASK/FSK 每 4 位数据编为 7 位汉明码字，经 FSK 或 ASK 调制后送入信道并按所选档位注入比特翻转干扰。
接收端 · Stage 7–9 纠错、拆帧与还原校验 解调并利用校验子修复单比特错，由 CRC-8 过滤双错坏帧与噪声包，最后解码文本并打印压缩率、BER 与纠错统计。
说明：纯软件数字通信教学仿真程序，不连接真实射频或串口硬件；测试项目基于 xUnit 与固定随机种子 42 编写了 50 余项可复现用例。
