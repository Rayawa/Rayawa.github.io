VideoTextGen

An OpenCode-orchestrated local video production workspace. It connects creative treatments, scripts, voice, alignment, direction, storyboards, assets, per-scene rendering, composition, QA, revision and delivery while keeping the runtime, versioned source and approved output cleanly separated.

At a glance

VideoTextGen splits local video production into 12 reviewable stages: script, narration, subtitle alignment, direction, storyboard, assets, per-scene rendering, composition, QA, revision and delivery. Structured contracts record the inputs and outputs of each stage, so a change only reruns the scenes it affects. About this project

What it addresses

Generated video commonly suffers from processes that cannot be reviewed and from whole-run reruns after a local change. This project splits production into stages governed by contracts, so the inputs, outputs, versions and review decisions of every step remain traceable.

How the pipeline is organised

A project contract and creative treatment are established first, then narration, timing alignment, storyboard and scene assets are generated in order. After per-scene rendering, technical QA runs and a delivered version is produced only once human review passes. When something changes, impact analysis comes first.

What it uses

OpenCode schedules the multi-stage tasks; Voicebox handles narration, WhisperX handles timing alignment, rendering runs on HTML Motion with Playwright, and composition uses FFmpeg. JSON Schema and hashes record the input-output relationships.

Safe delivery and recoverability

The workspace concentrates on production; the finished film only moves into the macOS Movies folder once it has been approved.

No overwrite

The delivery command never overwrites an existing version, so an approved film cannot be replaced by accident.

Code and film kept apart

The final video leaves the repository, leaving only a committable delivery record and full production provenance.

Rebuildable environment

Deleting .videoenv leaves source and projects untouched; rerunning setup restores the pinned environment.
