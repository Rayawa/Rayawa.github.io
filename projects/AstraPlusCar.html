AstraPlusCar

一辆从传感器到手机界面贯通的智能小车：设备端汇集相机和雷达数据，通过 ESP32 控制底盘；HarmonyOS 手机应用在同一局域网内预览画面并发送驾驶指令。

设备端代码 HarmonyOS 应用

项目速览

AstraPlusCar 把 HarmonyOS 手机、昇腾设备端和 ESP32 底盘串成一套智能小车系统。手机负责预览相机与雷达状态并发出驾驶意图；设备端处理传感器与接口，ESP32 执行具体硬件动作。项目重点是跨端协作和失联停车，实车联动仍需现场验收。

  • 三端协作手机、设备端与底盘通过局域网 HTTP 和串口各司其职。
  • 可见的驾驶状态画面、雷达、方向、速度和停车操作集中在手机端。
  • 安全边界松手停车与连接续期共同约束车辆动作。

用途与使用

用途

用于探索手机、边缘计算设备与底盘协同的智能车控制。驾驶者可在 HarmonyOS 手机上同时查看相机、雷达与车辆状态。

使用方式

将手机和设备端接入同一 WLAN，启动设备端服务并连接 ESP32 底盘，再在应用中填写设备地址。通过方向键、速度滑块和 STOP 控制车辆；实车操作前应核验停车逻辑。

技术与实现

Orange Pi AI Pro / 昇腾设备以 Python 提供 HTTP API 和传感器数据；ArkTS 应用负责界面；ESP32 经串口执行电机与舵机动作。续期机制约束运动指令。

成果与边界

页面链接设备端与 HarmonyOS 两个仓库。现有软件实现和文档可查，车轮方向、传感器联动及断联停车仍需实车验收。

项目概览

项目由两个独立仓库组成。设备端运行在 Orange Pi AI Pro / 昇腾开发环境，处理传感器、车辆控制和 HTTP API；手机端用 ArkTS 构建驾驶界面。既有设备代码还包含循迹、目标追踪等实验模块。

设备与底盘

设备端管理相机、雷达和车辆控制。高层动作通过串口传给 ESP32，由它负责电机和舵机等硬件动作。

手机控制

HarmonyOS 应用提供相机预览、雷达状态、方向控制、速度调节、停车和截图保存。

控制链路

手机和小车位于同一 WLAN。手机发送高层命令；设备端确认并执行，再由串口驱动 ESP32。相机和雷达数据沿相反方向提供给界面。

关键功能

画面与雷达

设备端共用相机画面提供实时预览和车端截图；雷达状态通过接口返回给手机，显示距离信息与设备状态。

驾驶交互

支持方向控制、速度步进与 0–100 速度滑块。方向键按住运动、松手停车；STOP 在驾驶界面持续可见。

控制保护

移动期间手机持续续期。断联、退到后台或设备端 600 ms 未收到续期时，控制流程要求停车；旧会话无法恢复先前动作。

双仓库协作

设备端和手机端分别维护，使用约定的 /api/v1 接口交互；硬件动作保留在设备侧，应用只发送高层控制意图。

当前进展

设备端和 HarmonyOS 应用已有对应实现与使用文档。应用构建及离线检查不能代替实车验收；车轮方向、相机/雷达联动、局域网连接和失联停车仍需在实车上确认。
